Antessala O que vamos construir, quem faz cada parte, e em que ordem.

Um aplicativo de mesa que roda sozinho no computador — sem internet, sem servidor, sem login. A pessoa entra por uma ficha simples, passa pela anamnese, e aparece numa fila que mostra quem deve ser chamado agora.

01
o que é

Quatro telas, e nada além disso

Cada tela tem uma função só. O que está escrito em vermelho em cada uma é o que ela deliberadamente não faz — tão importante quanto o resto.

tela 1

Entrada

Nome, sexo, idade e plano de saúde. Um botão para adicionar.

não procura ficha antiga
tela 2

Anamnese

Os blocos de perguntas já vêm carregados. Dá para acrescentar outros.

não mostra histórico
tela 3

Fila

Quem é o próximo a ser chamado, na ordem real, com o tempo de espera.

não escolhe o especialista
tela 4

Resumo

O especialista abre e vê o essencial pronto. Marca a jornada.

não edita a anamnese
02
a decisão que muda tudo

A pessoa não tem cadastro. Tem uma etiqueta.

Não existe prontuário nem histórico. Cada entrada é um registro novo e independente, mesmo que a pessoa já tenha passado por ali ontem.

É o mesmo comportamento do cadastro de exames do DietFlow: existem várias "glicose" cadastradas, e o sistema não reclama de repetido — cada uma é um item próprio.

O que isso elimina do trabalho

  • Nenhuma busca de paciente existente.
  • Nenhuma tela de evolução ou comparação — nenhuma.
  • Nenhuma regra de "esse nome já existe".
por que isso é bom O hospital não vai nos dar acesso ao cadastro real deles. Fingir que temos um seria a primeira coisa que a banca derrubaria.
03
o caminho de cada registro

Espera, é atendido, e volta a esperar

Cada mudança de etapa grava o horário. É isso que permite dizer, a qualquer momento, há quanto tempo aquela pessoa está parada.

Depois do especialista, a pessoa costuma voltar a esperar — por isso existe o hub. Um caso leve não pode envelhecer lá dentro, e é justamente por isso que o hub também precisa do seu próprio contador.

fora do escopo, de propósito O sistema não decide se a pessoa vai para o anestesista, para o cardiologista ou para um terceiro. Ele só mostra a ordem.
04
divisão do trabalho

Três frentes que não se atropelam

frente 1 · Claudeem andamento

Ambiente e telas

  • Preparar o aplicativo base: tirar tudo que não serve, deixar ele abrindo limpo.
  • Construir as telas 1, 2 e 4 — entrada, anamnese e resumo.
  • Guardar os registros no próprio computador, sem servidor.
frente 2 · Codexa iniciar

O motor da fila

  • A ordem de chamada: urgência combinada com tempo de espera.
  • Os estados da jornada e o carimbo de horário de cada mudança.
  • O contador do hub, para que um caso leve não fique esquecido.

É uma peça isolada e testada — não depende das telas para funcionar, e por isso pode ser feita em paralelo.

frente 3 · Zanpesquisa em curso

O catálogo de blocos da anamnese

  • Quais blocos de perguntas a triagem pré-anestésica precisa ter.
  • Quais desses o DietFlow já tem prontos para a gente trazer.
  • Quais precisam ser criados do zero, e o que cada um pergunta.

Não precisa ser bonito nem completo. Precisa ser uma lista. Cada linha preenchida vira um bloco na tela de anamnese.

para quem for abrir o código

Como rodar na sua máquina

Precisa de Node.js 20 ou mais novo instalado. Nada além disso — nem banco, nem servidor, nem chave de acesso para começar.

git clone <endereço do repositório>
cd antessala
npm install
npm run dev

A janela do aplicativo abre sozinha. Para gerar o programa instalável no fim, existe um comando de empacotamento — mas durante o trabalho, npm run dev é o suficiente.
